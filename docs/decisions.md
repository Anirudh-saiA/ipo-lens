# Decisions

Each entry: the choice, and why.

## Milestone 0 (2026-11-03)

- **Postgres image `pgvector/pgvector:pg16`.** Official pgvector build on Postgres 16; free and open source.
- **Host port 54329.** Ports 5432-5434 and 55432 are taken by other local Postgres instances on the development machine. Configurable via `POSTGRES_PORT`.
- **Surrogate `id` on every table.** The brief lists no id for `pages`, `subscription_snapshots`, `gmp_snapshots`, `lockins`, `doc_diffs` and `chunks`; a bigint `id` primary key is added so rows can be referenced and cited. Natural keys get unique constraints where they exist (`pages`: document_id + page_no).
- **Source page is NOT NULL** on `extracted_figures`, `risks` and `chunks` (hard rule 2: every figure stores its document and page).
- **Reported vs calculated kept apart.** `extracted_figures` holds reported numbers; `calculated_metrics` holds Python-computed values with `formula` and `input_figure_ids` pointing back to their inputs (hard rule 3).
- **Money and ratios as `NUMERIC`,** never float, so stored figures match the document exactly.
- **Enums as CHECK constraints on text columns,** not Postgres ENUM types, so adding a value is a simple migration.
- **Embedding dimension 384.** Fits small free local models such as bge-small-en-v1.5. Changing it later is one migration.
- **Migrations autogenerated by Alembic, then reviewed** (vector extension added by hand). A test checks they match the SQLAlchemy models, so drift is caught in CI.
- **Frontend tests with Vitest** (free, MIT).
- **No GitHub remote yet.** Waiting for the owner to create the `ipo-lens` repository.

## Milestone 1 (2026-11-03)

- **pdfplumber for page text and tables** (MIT; its dependencies pdfminer.six, pypdfium2 and Pillow are MIT/BSD/Apache). Docling stays as a second extractor for hard tables, to add only if pdfplumber misses tables.
- **New table `page_tables`.** The brief asks to store tables per page but its data model has no place for them. Each table is stored as found (rows as JSON, cell text untouched apart from trimming), with page number, position and the extraction method, before any interpretation.
- **Page numbers are 1-based PDF page indexes,** as shown in a PDF viewer's page box. Printed page numbers in a prospectus differ (the cover pages are unnumbered); citations will show the PDF page, and the printed number can be added later if users need it.
- **Ingestion is idempotent by sha256** and all-or-nothing: a document is committed only if every page was stored, so the stored page count always matches the PDF.
- **Tests use a separate `<db>_test` database,** created automatically, so migration tests never delete ingested documents.
- **Test PDFs are generated with reportlab** (BSD, dev only) instead of committing a real prospectus to the repo.
- **Ingestion is a command-line step for now** (`python -m app.cli ingest`). An upload endpoint and fetching from SEBI URLs come later; fetching needs rate limiting and caching per hard rule 9.

## Milestone 2, first pass on one prospectus (2026-11-03)

Started with the BCSSL RHP only, by choice; the gate needs 3 to 5 prospectuses, so it is not passed yet.

- **Figures come from the restated statement tables** (profit and loss, assets and liabilities, cash flow), found by the title at the top of the page. In BCSSL these are on pages 90 to 92. Other tables that repeat the same lines (KPI tables, ratio notes) are not used as sources, to avoid double counting.
- **Periods are read from the dates in the page header, not from column positions,** because extracted columns are often offset from their headers (page 91). A row is used only if it has exactly one value per period; otherwise it is skipped, not guessed.
- **Where a header prints the day apart from the month, the period ends on the last day of that month.** Restated periods in Indian prospectuses end on month ends.
- **Period labels:** `FY2026` (year to 31 March), `3M ended 2026-06-30` (part year), `as at 2026-03-31` (balance sheet).
- **A dash in a cell means nil** in prospectus tables. It is not stored as a figure, so a ratio needing it is skipped rather than computed with zero.
- **Basis:** `restated_consolidated` if the statement titles say so; `standalone` only when the document says it has no subsidiaries, or says standalone (BCSSL: page 406); otherwise `other`.
- **`calculated_metrics` gained `document_id`, `period`, `unit` and `note`** (migration 0003). The brief's columns cannot say which document or period a ratio belongs to.
- **Definitions:** EBITDA = profit before tax + finance costs + depreciation and amortisation. Adjusted EBITDA = EBITDA - other income (the RHP's own definition). Total debt = non-current + current borrowings, excluding lease liabilities (as in the RHP's ratio note). ROE uses average opening and closing equity; RoNW uses closing net worth.
- **Part-year ratios are labelled "not annualised".** ROE is skipped where the opening equity is not in the document (FY2024 here).
- **Not computed yet:** ROCE, because the RHP's capital employed uses tangible net worth and deferred tax liability, which are not extracted yet. Operating cash flow is extracted but not used in a ratio yet.
- **Accuracy counts a difference of 0.01 or less separately as "rounding",** never as exact. Example: the RHP's own total debt of 2,736.91 is 0.01 above the sum of its rounded borrowings lines (2,736.90).

## Milestone 2: second prospectus, Jio Platforms RHP (2026-11-03)

- **Statements drawn without ruling lines.** Jio's summary statements (PDF pages 75 to 77) have no table lines, so table extraction finds nothing. Ingest now also stores each word's position on the page (`pages.words`, migration 0004; older documents are backfilled by re-running `ingest`).
- **Second extractor, `statement-words v1`:** rebuilds value columns from the right edges of numbers, assigns each header date to the column it sits over, and joins labels that wrap around their numbers. It runs only on statement pages where the table method found nothing, so BCSSL results are unchanged.
- **A bare year in a header is a fiscal year only if the header says "Fiscal"** (fiscal year = year ended 31 March). Otherwise the page is skipped, not guessed.
- **"Summary of restated ... statement" titles count as statements** (the summary in "Summary Financial Information" is derived from the restated statements; the full statements later in the RHP are in a different layout and are not read yet).
- **PAT is "Profit for the period/year"** (after share of associates and joint ventures) when printed, ahead of an earlier "Profit After Tax" line.
- **Total equity, when not printed,** is calculated in Python as share capital + other equity + non-controlling interest and stored as a calculated metric with its inputs. ROE and RoNW for consolidated companies therefore use profit and equity including non-controlling interest; owners-only versions are a later improvement.
- **Total debt is borrowings only.** For Jio this leaves out large deferred payment liabilities for spectrum (about ₹1.05 trillion at 31 March 2026) and lease liabilities. Decided by the owner (2026-11-03): show both. `total_debt` and `debt_to_equity` stay borrowings only; `total_debt_incl_deferred_payments` and `debt_to_equity_incl_deferred_payments` add current and non-current deferred payment liabilities, and are computed only when both lines are printed (a missing line is not treated as zero). Jio, 31 March 2026: 0.21x borrowings only, 0.52x including deferred payments. Lease liabilities are in neither view.
- **Money results take the unit of their inputs** (million, lakh, crore), not a fixed "INR million".

## Milestone 2: third prospectus, Fusion CX RHP (2026-11-04)

- **Statement periods now always come from word positions when they are stored,** for the table method too. Fusion's cash flow header reads "April 1, 2026 to ended March 31, ... June 30, 2026 2026 2025 2024" in text order; pairing months and years in that order would give wrong periods with no error. Text-order pairing is kept only for pages stored without positions, and is never a fallback.
- **Header assignment:** touching pieces are joined first ("3" "1," -> "31,"; "M" "arch" -> "March"). A month belongs to the column region holding its centre (regions split at midpoints between value columns, since headers are centred or left-aligned and numbers right-aligned). A day or year belongs to its month: the nearest month to its left on the same line, else a month directly above or below it, else its region. In a range ("April 1, 2026 to June 30, 2026") the later date wins.
- **Operating cash flow label** now matches any "net cash ... operating activities" wording ("net cash flows generated from", "(used in)/generated from"), and was checked not to match investing or financing lines.
- Fusion CX is profitable in all periods, so the loss-making case is still untested.

## Milestone 3: offer structure and risk factors (2026-11-04)

- **New table `issue_facts`** (migration 0005): one row per fact about the offer, with page, printed wording (`value_text`), number only when printed (`value_number`), unit and source text. The brief's `ipos` table has no page columns, so it is left for a later step that fills it from cited facts.
- **"[●]" is stored as "[●] (not disclosed in this document)" with no number.** In all three RHPs the price band, bid lot and most share counts are [●]; they are published later (price band advertisement or addendum). Nothing is estimated.
- **Cover table:** columns are matched to "Fresh issue / Offer for sale / Total" by order of non-empty cells, because merged cells shift column indexes. "Not applicable" offer for sale is stored as 0 with that wording.
- **Dates** (anchor, bid open, bid close) come from the cover tables; a date split across rows without a year is skipped, and the first complete statement in the document is used.
- **Use of proceeds** is read from word positions on the "OBJECTS OF THE ISSUE/OFFER" pages (heading in capitals, so mentions inside risk factors do not count), from the first table that lists objects, stopping at "Net Proceeds"/"Total" or the next table. Wrapped labels are joined.
- **Risk factors:** from the "Risk Factors" heading to "SECTION III"; headings must run in number order (one missed number allowed), words inside detected tables are skipped, and a heading runs to the end of its first sentence. Result: 74/74, 65/65 and 75/75 headings, no gaps.
- **Risk categories use keyword rules on the cause part of the heading** (before "could/may/will ..."), since nearly every heading ends with "... financial condition". Stored with `category_method = "keyword rules v1"`; no AI. About 40% stay "uncategorised" rather than guessed, and some rules misfire (e.g. Fusion #4, revenue concentration, labelled "legal"). Better categorisation is an open item; an AI classifier would have to be labelled "AI interpretation" (hard rule 4).
- **Output labels in the API:** issue facts are "verified fact (from the document)"; risk headings are "company claim (disclosed risk factor)". Whether a keyword category needs its own label is an open question for the owner.
- **Not done:** promoter holding before and after the issue. Post-issue holding is [●] in all three RHPs, and pre-issue tables differ a lot between them.

## Prospectus web page, built before milestone 4 (2026-11-04)

- **Added to the plan by the owner's choice:** one page per prospectus showing data already extracted, so the work can be checked in a browser. It does not change the brief's feature order; the open IPO dashboard is still milestone 5.
- **Pages:** `/` lists ingested prospectuses; `/ipo/[id]` shows the offer, selling shareholders, use of proceeds, financial statements with a revenue/PAT chart (Recharts, MIT), calculated metrics split into "for each period" and "at each date", and risk factors grouped by keyword category.
- **Citations:** every value links to its PDF page (`p.N`), opening the stored page text from the API. Calculated metrics link to the pages of all their inputs. Output labels from hard rule 4 appear on every section, and the "research aid, not investment advice" notice is at the top.
- **No arithmetic in the browser.** Ratios are rounded half-up to 2 places in Python (`value_display`, `/documents/{id}/financials`); the browser only formats digits. A first version truncated in JavaScript (29.8483% showed as 29.84%), which is why this moved to the backend.
- **Server-rendered on every request** (`force-dynamic`), so the build does not need the API, and the page always shows the latest extraction. If the API is down, the home page says "Data unavailable".
- **Known dev-only warning:** `npm run dev` logs a React hydration warning on the risk list; the production build (`next build` + `next start`) has no console errors. Not investigated further.
- Jio Platforms' filing date was missing (not passed at ingest); set to 2026-10-14 from its cover page.

## Milestone 4 (local Q&A), more prospectuses, status and redesign (2026-11-04)

- **Q&A runs on free local models through Ollama** (owner's choice): `phi3.5` (Microsoft Phi-3.5-mini, MIT) answers; `snowflake-arctic-embed:33m` (Apache 2.0, 384 dimensions) embeds. Models avoided: Qwen 3B (non-commercial licence) and Llama (custom licence). All model calls go through `app/models_ai.py`, so a paid API can be swapped in later with the owner's approval.
- **Retrieval is hybrid:** embeddings plus Postgres full-text search, merged by reciprocal rank (migration 0006 adds the indexes). Chunks never span pages.
- **Answer guards in Python:** the model must return JSON with pages; pages must be among the retrieved excerpts; every number in the answer must be printed on the cited pages (blocks invented figures and model arithmetic); otherwise the answer becomes "Not enough evidence". Advice and prediction questions (apply?, listing gain, GMP) are refused before the model is called. Answers carry the label "AI interpretation".
- **Evaluation set** `data/golden/qa_eval.csv`: 22 answerable questions (expected value checked to be printed in the document) and 10 unanswerable. A citation counts as correct only if a cited page actually prints the expected value.
- **Four more SEBI documents** fetched by Claude at the owner's request from sebi.gov.in (official), one at a time with pauses: BLS Polymers RHP and price-band addendum, Acevector RHP (loss-making), SFC Environmental RHP. The SFC addendum is image-only (no text layer) and is not used; OCR would be needed.
- **Extraction fixes from the new layouts:** stray page-number text before titles; "Revenue From Operations (Net)"; "Statement of Profit & Loss"; "Summary of profit and loss on restated consolidated basis"; titles mid-page; statements continuing on the next page (accepted only if the very next page shows the same periods); rows split over two lines (joined by column position); headers whose dates are left-aligned over right-aligned numbers (columns taken from the line that prints every year); "loss" wording for loss-making companies; price band "PRICE BAND: ₹ 142 TO ₹ 150"; bid lot. Golden sets for BCSSL, Jio and Fusion were rerun after every change and stayed at 48 exact, 3 within 0.01, 0 wrong.
- **EBITDA starts from profit before exceptional items when printed** (Acevector FY2025 has a ₹736.05 m one-off loss), and from "profit before tax" rather than "before share of joint ventures" when both are printed.
- **ROE is refused when equity is zero or negative at either end of the year** (an average across negative and positive equity gives meaningless values).
- **EBITDA does not depend on GMP.** The owner asked for EBITDA to be prominent; it is now shown large with revenue and profit. It comes from the company's restated accounts, not market prices.
- **Status (open, upcoming, closed)** comes from the bid dates printed in each prospectus, compared with today's date. No market data source is used. On 4 Nov 2026 all six IPOs held are closed; upcoming ones need RHPs filed after 26 Oct 2026, which SEBI had not listed yet.
- **Site redesign at the owner's request:** light only (no dark mode), warm paper background, serif headings, one green accent; IPOs grouped by status; headline Revenue, EBITDA and PAT shown large; losses in brackets in muted red.
